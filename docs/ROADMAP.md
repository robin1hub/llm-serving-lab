# 多卡调度学习路线

记录日期：2026-10-15。用户目标是理解并研究D端压力下的调度，逐步扩展现有单卡模拟器。每次只完成一个可验证阶段，代码注释、章节讲解、ARCHITECTURE和HANDOFF同步维护。

| 顺序 | 功能范围 | 主要验收 |
| --- | --- | --- |
| 1（已完成） | 多个独立Mix worker，共享一个事件队列；各自队列、忙闲、Scheduler、Predictor、KV池和恢复状态 | 两卡计算区间可重叠；同卡不重叠；单卡旧结果不变；一张卡阻塞不阻止另一张运行 |
| 2 | 固定1P1D，加入KV传输与交接事件 | P产生首token；传输完成后D继续；耗时=固定延迟+字节数/带宽，先按链路串行 |
| 3 | 交接容量与等待协议 | 目标预留、源KV保护、提交/释放边界正确；目标容量不足时安全等待 |
| 4 | 可替换的请求路由 | 相同负载对比固定分配、轮询、最短队列、预计完成时间；统一统计窗口 |
| 5 | 面向D压力的调度 | 对比P准入/组批/路由对TTFT、ITL、吞吐和尾延迟的影响 |

第2阶段建立基本可运行交接，第3阶段再扩展容量不足等情况；在未实现相应协议前明确拒绝不支持的配置，不伪造成功。共享prefix、COW、多级缓存、TP/PP、MoE等不属于本轮范围。

## 当前阶段先固定的语义

- 每个worker对应一张独立逻辑GPU，均为完整Mix副本，拥有完整请求的Prefill和Decode。
- 使用显式固定请求归属表，帮助观察并发；不使用未来输出长度选择路由，不加入负载均衡算法。
- 全局只有一个future最小堆和一个模拟时钟；多卡并行通过重叠的模拟执行区间表达，不需要真实线程或GPU。
- 到达/完成/唤醒事件都带worker身份。同刻先处理全部到达、再全部完成、最后唤醒；稳定序号打破同类同刻并列。
- 允许复用不可变配置，但不共享运行中的队列、交替阶段、KV或恢复控制器。
- 参数可独立配置；初始教学例子的速度是假设，不使用A6000校准精度描述未经验证的多卡请求级结果。
- 单卡Python接口和旧JSON继续可用，旧结果语义保持；多卡结果必须能看出每轮属于哪张卡。

## 学习与实现顺序

先读第21章的数据归属表和手算时间线，再看WorkerConfig、事件中的worker_id，以及驱动共享事件队列的循环。之后阅读worker内的完成/选批方法；KV与重算细节仍参照第12–14章，不必一次读完所有代码。

本轮只启动本地逻辑模拟与测试，不部署服务、不连接服务器或占用真实GPU。完成第1阶段后先讲解结果，再讨论第2阶段。

第1阶段结果：示例A在卡0输出8/10/12ms，B在卡1输出4/6ms；93项测试中91通过、2项分词依赖缺失跳过。基础/KV/重算三个旧CLI结果完整JSON与改动前一致。第21章与HANDOFF记录当前实现，用户理解进度待确认。
